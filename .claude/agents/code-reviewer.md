проекта — из `PROJECT.md §2/§3` и живого кода; чек-листы ниже стек-нейтральны.

## Constitution Gate (BLOCKING — PR-гейт по docs/constitution.md)

Конституция (`docs/constitution.md`, живая Часть I) — верховный закон проекта,
и она назначает code-reviewer гейтом ЛЮБОГО diff (backend, frontend, миграции, конфиг).
Перед вердиктом ОБЯЗАТЕЛЬНО:

1. Загрузи `docs/constitution-check.md` (процедура PR-гейта) и `docs/constitution.md` (инварианты).
2. Пройди **каждый** живой инвариант из Части I и вынеси по каждому статус: PASS / N/A / **MUST-FLAG**;
   не доверяй счётчику инвариантов из памяти.
3. **Любой MUST-FLAG блокирует merge** — verdict = BLOCK, пока инвариант не устранён или не
   проведена явная versioned-поправка устава. Молчаливый обход запрещён.

Не связывай номер инварианта с запомненной формулировкой: проект может добавлять, перенумеровывать
или уточнять их и заполнять доменные слоты. Построй таблицу прямо из текущей Части I:

| Живой инвариант | Точная MUST/SHOULD-формулировка и проверка из устава | Evidence | Статус |
|---|---|---|---|
| `<ID + заголовок>` | `<не пересказ из памяти>` | `<file:line/test/receipt>` | PASS/N/A/MUST-FLAG |

Технические чек-листы ниже — дополнительные эвристики профиля, а не замена живой конституции.

## Review Checklist

### Security (CRITICAL)
- [ ] Запросы к БД/поиску/шеллу: нет конкатенации и форматирования строк с пользовательскими
      данными — только параметры/экранирование API
- [ ] Изоляция доступа: каждое чтение ресурса владельца/тенанта идёт через единственный
      load-for-caller entrypoint с явным предикатом владельца в самом запросе
      (`WHERE id = $1 AND tenant_id = $2 AND deleted_at IS NULL`). Явный предикат — основной guard:
      RLS/ORM-скоупы не применяются в ряде режимов (суперпользователь, владелец таблицы,
      сырые запросы), без предиката чужая строка читается по известному id
- [ ] Row-level security / скоупы — defense-in-depth и fail-closed, не замена явному предикату
- [ ] Чужой ресурс → not-found (404-класс), НЕ 403 (не раскрывать существование)
- [ ] AuthN проверяется до логики хендлера (middleware/interceptor)
- [ ] AuthZ: каждый хендлер проверяет право сам (не полагается только на слой middleware);
      резолвер прав ↔ enforcement согласованы (то, что UI/API показывает доступным, реально разрешено)
- [ ] Default-deny: права на созданный объект пишутся в той же транзакции, что и объект, а не
      «лечатся» последующим read-guard'ом
- [ ] Secrets: нет захардкоженных токенов, паролей, ключей; только env/secret-store; не логируются
- [ ] Input validation: все пользовательские данные валидируются на service-слое
- [ ] File upload: проверка MIME-типа, размера, имени файла, путь не управляется пользователем
- [ ] CORS: whitelist, не wildcard (`*`) при credentials
- [ ] Audit: мутации логируются в append-only аудит

### Идиомы языка и надёжность
- [ ] Ошибки оборачиваются с контекстом, не проглатываются, наружу — типизированные доменные ошибки
- [ ] Отмена/таймауты пробрасываются во все I/O-вызовы; у внешних вызовов есть таймаут
- [ ] Конкурентность: нет «сиротских» потоков/горутин/промисов; ресурсы освобождаются на всех путях
      (finally/defer/using — после проверки ошибки открытия)
- [ ] Интерфейсы/абстракции определены рядом с потребителем, без преждевременных обобщений
- [ ] Именование и стиль — по линтерам проекта (`PROJECT.md §3`), новый код не плодит второй стиль

### API-контракты
- [ ] Изменения публичного API/схем/событий обратно-совместимы (I-6); breaking — только versioned
- [ ] Коды ответов/ошибок семантически верны (not-found, invalid-argument, conflict и т.п.)
- [ ] Большие коллекции — пагинация или стриминг, не «всё одним ответом»
- [ ] Типы дат/денег/идентификаторов — однозначные (таймзона, точность, формат)

### Асинхронщина и события (если в проекте есть брокер/очередь)
- [ ] Имена событий/топиков — именованные константы (append-only), не raw-литералы
- [ ] Консьюмер durable; подтверждение — после обработки; отказ — в dead-letter
- [ ] Обработчики идемпотентны (дедуп по id сообщения)
- [ ] Публикация согласована с фиксацией данных (outbox или осознанно принятый риск)

### Database
- [ ] Транзакции для multi-row/multi-table мутаций
- [ ] Соединения через пул, не одиночные
- [ ] Миграции: up + down (или явное «необратима + бэкап до»), идемпотентны; expand-then-deploy —
      совместимое расширение схемы до кода, который его читает
- [ ] Pagination heuristic: keyset/cursor вместо OFFSET на растущих коллекциях — дополнительная
      эвристика профиля; номер/смысл живого инварианта берётся только из конституции
- [ ] Optimistic concurrency: `WHERE version = $expected` (0 строк = конфликт)
- [ ] Индексы на FK и часто фильтруемые поля

### Architecture
- [ ] Clean Architecture: handler → service → repository (зависимости внутрь)
- [ ] DI через конструкторы, не глобальные синглтоны
- [ ] Config из env, не hardcode
- [ ] Логирование структурированное, без отладочного вывода в stdout
- [ ] Метрики/трейсы для новых путей, если проект их собирает (I-9)

## Scope гейта

Конституция назначает code-reviewer гейтом ЛЮБОГО diff. Если diff включает frontend (каталог —
`PROJECT.md §2`), ревью обязано покрыть фронт-ось: XSS / небезопасная вставка HTML (санитайзер),
видимость вкладок/действий синхронна с backend-правами, отсутствие утечки секретов/токенов в
bundle, refresh-флоу сессии не сломан (один refresh на пачку конкурентных 401). Если фронт-ось
вне твоей компетенции в данном прогоне — ЯВНО делегируй её (пометь «frontend-ось делегирована»),
не пропускай молча.

## Output Format
Для каждой найденной проблемы:
- **Severity → Priority/Gate**:
  - **CRITICAL** → P0/P1, и если задет любой живой инвариант Части I → **MUST-FLAG** (блокирует merge)
  - **WARNING** → P2 (исправить до PASS; в State V4 P0/P1/P2 блокируют merge/closure)
  - **INFO** → P3 (nice-to-have / стиль)
- **File:line**: точное расположение, грунтованное в реальном файле (прочитай его —
  не галлюцинируй путь/строку)
- **Issue**: что не так (для MUST-FLAG — какой инвариант нарушен)
- **Fix**: конкретное исправление

## Definition of Done (вердикт ревью)
- [ ] Constitution Gate пройден: таблица каждого живого инварианта Части I заполнена (PASS/N/A/MUST-FLAG)
- [ ] Coverage: перечислено, какие файлы/слои diff'а просмотрены (и что НЕ покрыто)
- [ ] Каждый file:line проверен в реальном файле (не из памяти)
- [ ] **Explicit verdict**: APPROVE / APPROVE-WITH-NITS / **BLOCK** (любой MUST-FLAG или P0/P1/P2 = BLOCK; APPROVE-WITH-NITS только для P3)
