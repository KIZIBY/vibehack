# /intake — хотелка одной фразой → спека → (тикет) → /ship

Фраза владельца: **$ARGUMENTS**

**Единственный вход — `$ARGUMENTS`.** Внешние источники (webhook, e-mail, любые не-чатовые
входы) — вне scope; абстракцию «pluggable-источник intake» под них НЕ проектируй (YAGNI).

## Границы команды (прочти до действий)

- **/intake ≠ bug-intake §1 и ≠ /pipeline** — это диспетчер ПЕРЕД ними: жалобы тоже сюда,
  команда добавляет bug-specific diagnose/root-cause/scope-the-class contract из
  `docs/bug-handling-process.md`, а затем и `bugfix`, и `feature` создаёт со спекой (и тикетом, если
  активен GitHub-backend) и ведёт в `/ship`; формальный State V4 (`/pipeline-stage1`) — по явной
  просьбе владельца. Владелец не обязан знать
  синтаксис конвейеров и сам классифицировать вход; в формальном State V4 scope не даёт права
  обходить Design/Implementation/Evidence roots.
- **Сначала локальное и обратимое, потом внешнее.** `SPEC_DIR` и `state.md` создаются ДО любого
  внешнего тикета: сбой внешнего шага никогда не оставляет тикет-сироту и не останавливает спеку.
  Тикет — best-effort и догоняется позже; спека обязательна.
- **Секреты во фразе.** `scripts/intake.sh` сканирует summary и тело на секрет-паттерны
  (`scripts/secret-patterns.sh`) и отказывает (`error:secret-in-payload`), но это страховка, а не
  гарантия: фраза владельца уходит в тикет дословно, поэтому секреты и URL с токенами во фразе
  остаются ответственностью владельца.

## Шаг 1 — классификация bugfix/feature

Критерий — ТОТ ЖЕ, что в `/pipeline` → «Подготовка и resume», пункт 1 (Scope), и
`docs/bug-handling-process.md` (регрессия существующего поведения = bugfix; новая возможность =
feature). Критерий сюда НЕ копируется — прочитай его по этим двум ссылкам и применяй их
формулировку: ссылка вместо копии исключает дрейф формулировок между intake и `/pipeline`.

**Асимметричный bias при неуверенности:**

- интерактивная сессия → задай владельцу ОДИН уточняющий вопрос (I-13: не гадай, когда можно спросить);
- unattended-прогон → маршрут **feature** (консервативная семантика при неопределённости);
- классификация как `bugfix` без ЯВНОГО сигнала «это баг/регрессия» запрещена; оба scope проходят
  один fail-closed State V4 contract, поэтому классификация меняет доменную диагностику, но не гейты;
- пустая/односложная фраза: интерактив → один вопрос; unattended → отклони с подсказкой
  формата (`/intake "<фраза>"`); stage-1 на пустом входе не стартует.

## Шаг 2а — ветка bugfix: обогатить контекст и продолжить

Примени `docs/bug-handling-process.md` §1–§4: сохрани дословный симптом, severity, воспроизведение,
фальсифицируемую гипотезу, root-cause план и scope-the-class. Установи `SCOPE=bugfix` и продолжи
общий порядок ниже. Срочность повышает приоритет, но не отменяет architecture/TDD/review evidence;
`pipeline-state.sh init` обязателен и получает literal scope `bugfix`.

## Шаг 2б — общий порядок feature/bugfix (SPEC_DIR ДО тикета)

Для новой возможности установи `SCOPE=feature`; для ветки 2а сохрани `SCOPE=bugfix`.

0. **Advisory спек-дедап:** штатным Grep-tool поищи ключевые слова фразы по
   `specs/*/spec.md` и `specs/*/state.md` — фраза/слова передаются как ПАРАМЕТР Grep-tool,
   shell-команду `grep "<фраза>"` не собирай (инъекция через фразу). Совпадение → спроси владельца:
   «похоже, уже есть specs/NNN-…, продолжить?» — это advisory, не блокер: при подтверждении
   (или в unattended) продолжай.
1. **NNN/slug + mkdir-guard:**
   - **Fetch ПЕРЕД расчётом NNN** (сужает окно гонки номеров между worktree):
     сперва `git remote get-url origin` — есть ли вообще remote:
     - remote ОТСУТСТВУЕТ (вывод пуст / команда упала — локальный проект без origin) → тихо
       пропусти fetch, номер считай по локальному `specs/`; это НОРМА локального клона, не
       предупреждение (не пиши advisory-warn).
     - remote есть → `git fetch origin` под alarm-таймаутом, например обёрткой
       `net() { perl -e 'alarm shift; exec @ARGV' 15 "$@"; }` (зависшая сеть не вешает /intake).
       Fetch УСПЕШЕН → NNN считай по ОБЪЕДИНЕНИЮ локального `specs/` и `origin/main:specs/`: `git ls-tree --name-only origin/main specs/` (номера уже занятых на
       origin спек) ∪ локальный список каталогов `specs/`, взять max NNN + 1. Fetch УПАЛ
       (сеть/таймаут при существующем origin) → advisory-warn владельцу: «origin недоступен,
       номер по локальному `specs/` — риск гонки номеров принят», продолжай по локальному `specs/`.
   - NNN = следующий номер (три цифры) по объединённому списку выше, slug =
     транслитерация первых 3-4 слов фразы. `mkdir "specs/<NNN>-<slug>"` — атомарный POSIX-guard
     гонки номеров (вторая линия: fetch сужает окно, mkdir-guard страхует атомарно).
     EEXIST → пересчитай NNN и повтори ОДИН раз; второй EEXIST подряд → СТОП с
     ошибкой владельцу (чужой N без проверки slug не занимать). Дальше `SPEC_DIR=specs/<NNN>-<slug>`.
2. **Init:** `bash scripts/pipeline-state.sh init "$SPEC_DIR" "<фраза>" "$SCOPE"` — 5-й
   позиционный (ticket) НЕ передавать, тикета ещё нет.
   - state.md уже существует → это **resume** (повторный /intake той же фразы): скрипт покажет
     `next:` — продолжай оттуда, новый SPEC_DIR не создавай (шаг 3 при этом безопасен: dedup
     поймает существующий тикет, link-ticket идемпотентен).
   - init упал FATAL **не** по scope-guard и **не** resume (права на specs/, диск, «N занят»
     после повтора) → СТОП: покажи владельцу die-текст дословно и тикет НЕ создавай
     (иначе появляется тикет-сирота без спеки).
3. **Тикет (опционально, best-effort):**
   `bash scripts/intake.sh ticket "$SPEC_DIR" "<summary>" "<фраза дословно>"` — summary = краткая
   тема (сама фраза, если она ≤ ~100 символов); 4-й аргумент — фраза ДОСЛОВНО, без редактуры.
   Активный issue-backend скрипт разрешает сам по правилу `agents/README.md` → «Режим задач
   (ISSUE MODE)» (переменная окружения `ISSUE_BACKEND` → иначе строка `ISSUE_BACKEND=` в
   `PROJECT.md §7` → иначе `none`) — не вычисляй его вручную и не подменяй вызов догадкой. При
   `github` скрипт берёт репозиторий только из `origin`, ставит префикс автора, дедапит,
   verify-читает и вызывает link-ticket. Исход — одна строка stdout:
   - `skipped:issue-backend-none` → внешнего трекера нет, ни одного внешнего вызова не было; KEY
     пуст. Одной строкой сообщи владельцу: «тикет не создаётся (`ISSUE_BACKEND=none`) — работа
     живёт в `$SPEC_DIR`; очередь задач проекта — `docs/backlog.md`». Дальше шаг 4;
   - `created:<KEY>` → запомни KEY для маркера шага 4;
   - `deferred:public-repo` → в интерактиве покажи владельцу: «репозиторий PUBLIC — дословная
     фраза уйдёт в публично читаемый issue», дождись ЯВНОГО confirm → повтори тот же вызов с
     `INTAKE_ALLOW_PUBLIC=1`; отказ владельца или unattended → продолжай без тикета (KEY пуст);
   - прочие `deferred:*` → покажи владельцу ОДНУ строку-рецепт со stderr скрипта
     («Тикет отложен: … догон: `bash scripts/pipeline-state.sh link-ticket …`») и продолжай:
     спека обязательна, тикет догоняется (I-8); KEY пуст (кроме `verify-failed KEY=<key>` —
     покажи KEY владельцу для ручного link-ticket после проверки, маркер НЕ ставь);
   - `error:invalid-issue-backend` → конфигурация backend невалидна (fail closed): тикет не
     создаётся, покажи владельцу причину одной строкой, конфигурацию молча не чини;
   - прочие `error:*` → покажи причину; в обоих случаях stage-1 всё равно продолжается без Ticket
     (KEY пуст).

   Никогда не обходи исход скрипта другим транспортом (ручной `gh issue create`, другой трекер) и
   не пиши «тикет создан» без строки `created:<KEY>`.
4. **Спека + маркер:** делегируй механику `/speckit.specify "<фраза>" SPEC_DIR=$SPEC_DIR` —
   сырая фраза идёт как есть (доуточнение — зона NEEDS CLARIFICATION спеки и `/speckit.clarify`
   внутри stage-1; отдельный clarify-гейт не строится). Затем маркер в шапке spec.md —
   только `perl -pi -e` (BSD/GNU-нейтрально; `sed -i` запрещён). ВАЖНО: маркер —
   канонический **bullet** `- Источник: тикет KEY` (blockquote `>` НЕ распознаётся
   `spec-lint.sh`/`dora-metrics.sh`):
   - KEY непуст:
     `grep -qE '^[-*>]?[[:space:]]*Источник: тикет ' "$SPEC_DIR/spec.md" || KEYV="<KEY>" perl -pi -e '$_ .= "\n- Источник: тикет $ENV{KEYV}\n" if $. == 1' "$SPEC_DIR/spec.md"`
   - KEY пуст: `perl -pi -e '$_ = "" if /^[-*>]?\s*Источник: тикет/' "$SPEC_DIR/spec.md"` — строка
     удаляется целиком, шаблонный плейсхолдер не остаётся. Проверь: `bash scripts/spec-lint.sh "$SPEC_DIR"`
     не даёт тикет-warn на пустом месте.
5. **Авто-старт:** по умолчанию — лёгкий конвейер `/ship "<фраза>"` (спека `$SPEC_DIR` — его контекст).
   Только если владелец явно попросил формальный конвейер или работа регулируемая — делегируй
   `/pipeline-stage1 "<фраза>" SPEC_DIR=$SPEC_DIR SCOPE=$SCOPE` — именно механику stage-1, не полный
   `/pipeline` с нуля (resume-семантика init делает повторный вход безопасным). Дальше работает
   выбранный конвейер — /intake его не дублирует.
