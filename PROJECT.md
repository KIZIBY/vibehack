# PROJECT.md — паспорт проекта

> Единственный файл, который заполняется при установке харнесса в проект. Каноны агентов,
> runtime-команды и доктрины ссылаются на разделы этого файла (`PROJECT.md §3 Команды` и т.п.)
> вместо плейсхолдеров. Значение `-` означает «осознанно не применимо» (N/A); `ЗАПОЛНИ` —
> ещё не заполнено, и агент обязан спросить владельца, а не угадывать.
>
> Секреты сюда **не пишутся никогда** — только ИМЕНА переменных окружения или ссылки на
> secret-store. Пути конкретной машины (`/Users/...`, `/home/...`) — тоже нет.

## 3. Команды

| Назначение | Команда |
|---|---|
| Установка зависимостей | `bash scripts/setup.sh` (создаётся задачей T010) |
| Сборка | `bash scripts/build.sh` — сборка frontend (T010) |
| Линт / проверка типов | `bash scripts/lint.sh` (T010) |
| Unit-тесты | `bash scripts/test-unit.sh` — backend, intake, hermes, frontend; принимает каталог зоны (T010) |
| Интеграционные тесты | `bash scripts/test-integration.sh` — backend + intake + fake-шлюз агентов (T010) |
| E2E / браузерные тесты | `bash scripts/test-e2e.sh` — Playwright по критическим маршрутам §8 (T010) |
| Локальный запуск | `bash scripts/dev.sh` — backend, frontend и fake-шлюз агентов (T010) |
| Миграции | `bash scripts/migrate.sh` (T012) |
| Деплой | `bash scripts/deploy.sh` (T095); агентский слой — `bash hermes/deploy.sh` |
| Откат | `bash scripts/rollback.sh` (T095) |

Формальный `/pipeline` исполняет RED/GREEN-доказательства только через `/bin/bash`, `/bin/sh`,
`/usr/bin/perl` или исполняемый (`100755`) wrapper внутри репозитория с таким shebang. Если тесты
запускаются через `npm`, `go`, `pytest` и т.п., оберни команду в такой wrapper (например
`scripts/test-unit.sh`) и укажи его здесь.

Линт и тесты из этой таблицы подключаются в помеченный блок `scripts/check.sh` — единой проверки,
которую агенты и люди запускают перед каждым коммитом.

## 7. Трекер задач

Строку ниже читают скрипты (`scripts/intake.sh`, `scripts/agent-preflight.sh`,
`scripts/issue-token-lifecycle.pl`); переменная окружения `ISSUE_BACKEND` имеет приоритет.

```
ISSUE_BACKEND=none
```

- `none` — внешнего трекера нет: работа описывается в `specs/`, очередь задач — `docs/backlog.md`.
- `github` — GitHub Issues через `gh`. Репозиторий всегда берётся из `origin`; авторизация — штатная
  `gh auth login`, токены в репозиторий не попадают.

Правила работы с задачами для агентов: `agents/README.md` → «Режим задач (ISSUE MODE)».
