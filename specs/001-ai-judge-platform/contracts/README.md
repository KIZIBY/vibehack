# Контракты зон — AI-судья

Контракты — то, что позволяет четырём сессиям работать параллельно и не ломать друг друга. Они
**заморожены** после задачи T011 (устав I-6): поле нельзя удалить или переименовать; добавить можно
только необязательное поле, а несовместимое изменение — новая версия схемы (`schema_version`) и
решение владельца.

| Файл | Кто пишет | Кто читает | Что фиксирует |
|---|---|---|---|
| `openapi.yaml` | зона A (backend) | зона D (frontend), E2E | REST `/api/v1` и события SSE |
| `inventory.schema.json` | зона B (intake) | A, C (агенты читают опись) | опись материалов одной работы |
| `similarity.schema.json` | зона B (intake) | A, C (`critic-uniqueness`) | пары похожих работ внутри проекта |
| `agent-report.schema.json` | зона C (плагин `ai-judge`) | A (принимает отчёты) | документы, которые роли сдают инструментами |
| `journal-event.schema.json` | зоны C и A | A, D (лента журнала) | одна строка журнала |
| `agent-run.md` | зоны A и C | A, C | запуск роли, раскладка файлов на общем томе, соглашения |

## Как зоны разъединены (тест-дублёры)

| Зона | Работает без… | Через что |
|---|---|---|
| D (UI) | настоящего backend | мок-сервер по `openapi.yaml` (MSW), примеры ответов — в самой схеме |
| A (backend) | Hermes и OpenAI | `FakeAgentGateway`: отдаёт заранее записанные отчёты из `tests/fixtures/agent-reports/` |
| A (backend) | настоящего intake | готовые `inventory.json` из `tests/fixtures/inventories/` |
| B (intake) | backend | запускается как `python -m intake <каталог работы> --out <каталог>` и пишет `inventory.json` |
| C (agents) | backend | `hermes/scripts/run_role.sh <role> <каталог работы>` ходит прямо в шлюз и складывает отчёт в файл |

## Как менять контракт

1. Правка контракта — отдельный PR только с файлами из этого каталога и тестом
   `tests/contracts/test_contracts.py`.
2. В описании PR — кого из зон это задевает; затронутые зоны подтверждают правку до merge.
3. Фикстуры в `tests/fixtures/` обновляются в том же PR, иначе тест контрактов красный.
