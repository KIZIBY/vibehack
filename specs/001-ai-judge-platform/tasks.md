# Tasks: AI-судья

Спека: `spec.md` · план: `plan.md` · контракты: `contracts/`. Формат строки:
`- [ ] T### [P] [зона] [US#] описание с путями`. `[P]` — можно делать параллельно с другими зонами.
Поведенческая задача начинается с падающего теста (RED), затем реализация (GREEN) — это шаги `/ship`.

## Как работать несколькими сессиями

Зон четыре, и больше четырёх worktree на одной машине устав не разрешает (I-15). У каждого человека
свой клон и свои worktree, поэтому команда из 6–8 человек укладывается в правила: лимит считается на
checkout, а пересечения по файлам ловят lease и зоны.

Старт почти без ожидания: **все стартуют сразу после того, как спека с контрактами закоммичена** (иначе
в worktree не будет контрактов). Фундамент нужен только как опора, а не как шлагбаум:

| Фаза | Кто | Что блокирует |
|---|---|---|
| 0. Спайки T001–T003 | человек из зоны C (T001, T003) и B (T002) | T062 и T069 ждут T001, T046 ждёт T002, T066 ждёт T003 |
| 1. Фундамент T010–T014 | один человек, первым делом | зона A ждёт T012 и T013 (БД, фикстуры); всем нужны T010 (`test-unit.sh`) и T011 для `check.sh` перед публикацией; зоны B, C, D пишут код и тесты в своих каталогах нативными раннерами (pytest, vitest), пока обёртки нет |
| 2. Зоны A, B, C, D | по человеку на зону (или больше — см. «Распределение») | зоны друг друга не ждут, только контракты |
| 3. Сборка T090–T097 | те, кто закончил срез S0 в своей зоне | зоны влиты в `main` |

Запуск зоны или трека:

```bash
bash scripts/ship-worktree.sh new <slug>          # ветка ship/<slug> и worktree рядом с репозиторием
cd <напечатанный путь>
bash scripts/coordination-lease.sh take <slug> subsystem 8 <пути зоны из таблицы>
# дальше по задаче: /ship "T0xx <описание из этого файла>"
```

| Зона | `<slug>` | Пути (lease) | Тест-команда зоны | Работает без остальных благодаря |
|---|---|---|---|---|
| A. Backend | `backend` | `backend/**` `tests/backend/**` | `bash scripts/test-unit.sh backend` | `FakeAgentGateway`, фикстуры описей (контракт) |
| B. Intake | `intake` | `intake/**` `tests/intake/**` `tests/fixtures/submissions/**` | `bash scripts/test-unit.sh intake` | запуск как CLI, backend не нужен |
| C. Агенты | `agents` | `hermes/**` | `bash scripts/test-unit.sh hermes` | `hermes/scripts/run_role.sh`, backend не нужен |
| D. Frontend | `frontend` | `frontend/**` | `bash scripts/test-unit.sh frontend` | мок-сервер MSW по `openapi.yaml` |

Правила на всех:
- Файлы чужой зоны не трогаем. Нужна правка общего файла (`scripts/check.sh`, `PROJECT.md`, `docs/**`,
  `contracts/**`) — отдельный маленький PR, о нём предупреждаем остальные сессии (контракты — по
  `contracts/README.md`).
- Один merge в `main` за раз (`scripts/agent-publish-main.sh`, устав I-15). Перед публикацией —
  `git fetch` и ребейз на `main`.
- Сессия закрывает задачи в этом файле (`- [x]`) в том же PR, что и код. Конфликты в `tasks.md`
  решаются построчно: каждая зона правит только свой раздел.
- Старт сессии: `bash scripts/telemetry.sh task estimate …`, конец: `task done` (память проекта).

## Распределение между людьми

Срезы — по `docs/design-doc.md` §12. **Сначала весь срез S0 во всех зонах — это работающее демо**, потом S1 и
дальше. Метка `[S0]`…`[S3]` стоит у каждой задачи.

| Срез | Что получаем |
|---|---|
| S0 «Скелет» | проект → вводные → рубрика → решения → оценка ролью `code` → таблица оценок → модальное окно пояснения |
| S1 «Полная команда» | роли `business`, `design`, оба критика, лента журнала, прогресс в реальном времени, выкатка |
| S2 «Доверие» | ручные правки, перезапуск, сравнение работ между собой, злой корпус, замеры и калибровка |
| S3 «Режимы» | ML-хакатон (метрики), домашние задания, выгрузка CSV |

| 5 | #1: F → A1. #2: A2. #3: B1 + B2. #4: C1 + C2 (+X). #5: D |
| 6 | #1: F → A1. #2: A2. #3: B1 + B2. #4: C1 (+T001, T003). #5: C2. #6: D |

Рекомендация на 4 человека: зона на человека. Кто закончил S0 раньше, берёт S1 соседа, а не сидит без дела:
свободный человек выбирает первую незанятую `[ ]` задачу следующего по очереди среза из чужого трека
и пишет об этом в чат.
