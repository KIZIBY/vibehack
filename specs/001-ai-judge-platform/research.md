# Research — AI-судья

Решения для плана. Источники: `docs/design-doc.md`, документация Hermes Agent (через Context7:
user-guide/api-server, toolsets, configuration, providers), спека. Что не проверено на живом Hermes,
помечено **[спайк]** и закрывается задачами T001–T003.

## R1. Как backend запускает роли

- **Решение:** `POST /v1/runs` + опрос `GET /v1/runs/{id}` + SSE `…/events` для прогресса.
- **Почему:** запуск принимает `session_id`, `instructions`, `input`, `Idempotency-Key` (повтор после
  сбоя не плодит дубль); статус отдаёт `usage` и `runtime` (фактические провайдер и модель — основа
  честных токенов, NFR-009); события дают `tool.started/completed` для ленты прогресса.
- **Альтернативы:** `/v1/responses` — хранит состояние беседы, но без идемпотентности и статусов
  запуска; `/v1/chat/completions` — для чат-клиентов, не для пакетов.
- **Ограничение:** по умолчанию 10 одновременных запусков, лишние — `429`. Backend держит собственный
  семафор ниже предела (по умолчанию 8) и повторяет после `429` (FR-014, NFR-002).

## R2. Структурный результат роли

- **Решение:** роль сдаёт результат вызовами инструментов плагина (`report_scores`, `report_flag`,
  `report_claims`, `report_rubric`, `report_ux_metrics`, `report_inventory_patch`); плагин проверяет
  документ по JSON-схеме, при ошибке возвращает модели текст ошибки (она правит вызов в том же запуске),
  принятый документ пишет файлом на общий том.
- **Почему:** статус запуска возвращает только итоговый текст, а не аргументы вызовов; файл на томе —
  устойчивый след, который переживает рестарт шлюза; валидация в плагине даёт самоисправление, а
  повторная валидация в backend — защиту от ошибки плагина.
- **Альтернативы:** парсить JSON из текста ответа (хрупко, ломается на «пояснениях»); колбэк плагина
  в backend по HTTP (лишняя сетевая зависимость агентского слоя от backend).

## R3. Ограничение инструментов по ролям **[спайк T001]**

- В Hermes наборы инструментов задаются на платформу (`platform_toolsets.api_server`), а не на запрос.
  Есть мультипрофильный шлюз (`/p/<profile>/v1/...`, у профиля свой конфиг), но то, что профиль
  применяет свои toolsets к запросам через `api_server`, в документации прямо не сказано.
- **Решение пока:** вариант 1 — профиль на роль; вариант 2 — хук `pre_tool_call` плагина с белым
  списком по роли из `session_id` (хук умеет блокировать вызов — `hermes/README.md`). Выбираем по
  результату спайка; безопасный минимум в обоих случаях — у `code` и `critic-*` нет терминала.
- **Критерий выбора:** инструмент вне белого списка роли невозможно вызвать — проверяется тестом, в
  котором роли `code` предлагают выполнить команду.

## R4. Подписка OpenAI и параллельность **[спайк T001]**

- Вход: `hermes model` → «ChatGPT or Codex Subscription» (провайдер `openai-codex`, `model.default` —
  имя модели OpenAI). Токен OAuth хранится на сервере в `~/.hermes`.
- **Неизвестно:** лимиты подписки на параллельные запросы и объём. Спайк даёт: сколько запусков
  `code` идут одновременно без `429` от провайдера, время и `usage` на репозиторий среднего размера.
- **Запасной путь:** ключ API (`OPENAI_API_KEY` в `~/.hermes/.env`) без смены кода; число параллельных
  работ в backend — настройка (`JUDGE_MAX_PARALLEL_SUBMISSIONS`, по умолчанию 5).

## R5. Расшифровка скринкаста **[спайк T002]**

- Подписка покрывает чат-модели; распознавание речи может требовать ключа API, поэтому на демо
  берём локальную модель `faster-whisper` (малая) в intake.
- **Критерий:** 10 минут русской речи обрабатываются ≤ 6 мин на 2 vCPU; иначе — только кадры и описание
  через `vision_analyze`, с пометкой в описи (FR-012, Edge Cases про скринкаст).

## R6. Браузер дизайнера **[спайк T003]**

- В Hermes есть `browser_*` (скриншоты, консоль, `browser_vision`); для работы нужен Chromium в
  контейнере. Проверяем, что в образе `nousresearch/hermes-agent` headless-браузер запускается на 2 vCPU /
  4 ГБ и держит 2–3 одновременные сессии. Не получилось — отдельный контейнер Playwright, из которого
  intake снимает скриншоты, а дизайнер оценивает по ним (оценка менее «живая», но проходит NFR-001).

## R7. Intake как отдельный процесс

- **Решение:** `python -m intake <каталог работы> --out <каталог>`; backend запускает подпроцесс с
  таймаутом и лимитами (CPU, память, файлы, время), результат — `inventory.json`.
- **Почему:** код участников не исполняется, но парсеры форматов (PDF, PPTX, архивы) — самая рискованная
  поверхность (NFR-011); подпроцесс с лимитами изолирует сбой и позволяет тестировать зону независимо.
- **Альтернатива:** библиотека внутри backend — проще, но падение парсера роняет API.

## R8. Подсчёт итога

- **Решение:** одна функция `compute_score` в `hermes/plugins/ai-judge/tools.py` (чистый stdlib).
  Backend загружает её тонким загрузчиком `backend/app/scoring.py` через `importlib` по пути файла и
  покрывает кросс-тестом (устав I-4: один источник истины).
- **Альтернатива:** вынести в отдельный пакет `judge_core` — чище, но плагину в контейнере доступна
  только его папка (`docker-compose.yml`: том только `plugins/ai-judge`); потребует менять монтирование.
  Рассмотреть после хакатона.

## R9. Межкомандный антиплагиат

- **Решение:** intake считает отпечатки (токены кода, окна по 5 токенов, winnowing) по всем работам
  проекта и пишет `similarity.json`; `critic-uniqueness` читает готовый результат и проверяет веб.
- **Почему:** сравнение «все со всеми» — вычисление, а не рассуждение; модели оставляем интерпретацию
  («заимствование шаблона» против «копирование решения»).
- **Ограничение:** шаблонный код (стартеры, сгенерированные файлы, `node_modules`) отфильтровывается
  списком исключений; порог флага — по золотому набору (T091).

## R10. Хранение и срок жизни материалов

- Фоновая задача раз в час находит проекты, где `last_activity_at + retention_days` прошло, удаляет
  содержимое каталогов `projects/<p>/{briefs,submissions}`, ставит `material.status='deleted'`,
  `purged_at`, пишет событие `purge` (FR-031, NFR-013, устав I-1/I-2). Оценки, флаги и журнал остаются.

## R11. Прогресс в реальном времени

- **Решение:** SSE от backend (`GET /api/v1/projects/{id}/events`), клиент после обрыва перечитывает
  состояние запросом. **Почему:** односторонний поток, проще WebSocket, работает через обычный прокси;
  потерянные события не критичны (состояние восстанавливается GET).

## R12. Frontend

- React + Vite + Tailwind (принято). Раскладка «чат с сайдбаром» — свой компонент; таблица оценок —
  обычная таблица с сортировкой на клиенте (до 200 строк × 30 столбцов, NFR-003/004); модальные окна — на
  нативном `<dialog>` (фокус-ловушка и Esc бесплатно). Моки для разработки без backend — MSW по `openapi.yaml`.
