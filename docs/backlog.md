# Backlog — очередь задач проекта

> Ведётся, когда у проекта нет внешнего трекера: `ISSUE_BACKEND=none` (`PROJECT.md §7`). Тогда
> задача = запись в этом файле, а работа по ней — каталог `specs/NNN-slug/`. При
> `ISSUE_BACKEND=github` задачи живут в GitHub Issues, а этот файл не используется — в том числе как
> fallback при недоступности GitHub (это `BLOCKED: issue-backend-unavailable`). Правила для агентов —
> `agents/README.md` → «Режим задач (ISSUE MODE)».

## Формат записи

Каждая задача — раздел третьего уровня в «Задачах» ниже:

```markdown
### B-001 · [<роль>] <тема>

- **Тип:** feature | bug
- **Приоритет:** P0 | P1 | P2 | P3
- **Статус:** open | in-progress | blocked | done | duplicate | deferred | needs-oracle
- **Спека:** `specs/NNN-slug/` (когда работа начата) или `-`
- **Создано:** YYYY-MM-DD · <источник: владелец / роль / `/intake`>

<Тело. Для bug — секции из `docs/bug-handling-process.md` §1: Контекст (дата + цитата), Симптомы,
Возможные причины, Желаемое поведение (чек-лист приёмки), Severity, Связанные.
Для feature — что и зачем, критерии приёмки.>

**Журнал:**
- YYYY-MM-DD · [<роль>] <комментарий, evidence, смена статуса>
```

Правила:

- **Id** `B-NNN` растёт монотонно и не переиспользуется; `[<роль>]` в заголовке — автор записи
  (`developer`, `visual-qa`, … или `owner`).
- **Dedup до добавления:** поиск по этому файлу и `specs/`; совпало — дополняй существующую запись.
- **Записи не удаляются.** Статус меняется правкой поля, а каждое событие (комментарий, новая
  evidence, смена статуса) — новой датированной строкой в «Журнале» записи; прошлые строки не
  переписываются.
- **`done`** — только после опубликованного SHA и того же evidence-гейта, что для тикета
  (`docs/bug-handling-process.md` §8); SHA и evidence пишутся строкой журнала. `duplicate`,
  `deferred`, `needs-oracle` — явно, со ссылкой на маршрут.
- Порядок разделов — по времени создания; приоритет задаёт поле, а не позиция.
- Секреты и пути конкретной машины сюда не пишутся (`AGENTS.md` → «Секреты и приватность»).
- Правка файла — обычное изменение репозитория: `bash scripts/check.sh`, коммит, публикация по
  `docs/guides/GIT_PUBLISH_RUNBOOK.md`.
