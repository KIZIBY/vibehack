# MEMORY_CONVENTION.md — единая конвенция персистентной памяти агентов

Версия: v1.0
Scope: все роли команды (`agents/roles/*.md`). Состав ролей и маршрутизация — `agents/README.md`.
Каноны ролей НЕ дублируют эти правила — только ссылаются сюда (допустима одна строка-указатель +
ролевые дельты). Сам файл памяти МОЖЕТ держать краткий блок «Правила памяти» с ролевыми дельтами, но
указатель на эту конвенцию обязателен, и при расхождении конвенция главнее.

## 1. Имена файлов

- Компакт: `agents/memory/<role>.md`, где `<role>` — id роли (`developer`, `repo-hygiene`, `tech-writer`,
  `visual-qa`, `ux-route-qa`, `workflow-qa`, `chaos-qa`, `regression-qa`).
- Архив: каталог `agents/memory/archive/<role>/`, файлы `<YYYY-MM>.md` (месяц исходной записи). Для
  смешанных блоков допустим суффикс: `<YYYY-MM>-runs.md`.
- Других мест для памяти нет: память в чужих каталогах, в `/tmp` или только в контексте сессии не считается
  сохранённой.

## 2. Двухуровневая структура

**Компакт** (`agents/memory/<role>.md`) — единственный файл, который роль обязана читать перед прогоном.
Hard-лимит: **1500 строк** (`wc -l`) **И ≤60 KB** (`wc -c`) — что наступит раньше. Оба лимита нужны:
строковый лимит «легально» обходится удлинением строк, а стоимость чтения — это ТОКЕНЫ (≈ байты/4), не
строки; активная роль платит её каждый прогон. Содержит:

- durable-слой (НЕ ротируется): правила памяти, снимок роли, coverage taxonomy, recurring patterns /
  кластеры задач, известные слепые зоны, standing-rule checklists, routing, промахи и коррекции, lessons
  learned, open backlog, self-audit checklist, State (если роль его ведёт);
- журнальный слой: минимум **последние 3 прогона** (полные записи);
- ⤵-указатели на отротированные блоки (что и куда переехало, с датой ротации).

**Архив** (`agents/memory/archive/<role>/*.md`) — полная история. Читается ТОЧЕЧНО (grep по задаче / дате /
теме), целиком НЕ читается и в read-before-run НЕ входит.

## 3. Инварианты (data sacred)

1. **Append-only.** Ничего не удаляется и не редактируется задним числом. Опровергнутая запись помечается
   `superseded: <дата> → see <new entry>`.
2. **Ротация = перенос, не правка.** Строки переезжают в архив БЕЗ изменений (byte-exact), на их месте
   остаётся одна ⤵-строка-указатель. Сверка обязательна:
   `строк(оригинал) == строк(новый компакт) + строк(перенесено) − указатели`.
3. **Никаких секретов.** Пароли, токены, cookies, session ID, полные auth-заголовки — запрещены и в компакте,
   и в архиве, и в evidence.
4. **Никаких путей конкретной машины** (`/Users/...`, `/home/...`) — только пути от корня репозитория.

## 4. Создание памяти при первом прогоне

Файла памяти до первого прогона роли нет — это норма. Роль, не найдя `agents/memory/<role>.md`, создаёт его
по шаблону ниже (первый прогон = калибровка), заполняет журнал этого прогона и коммитит вместе с результатом
прогона по `docs/guides/GIT_PUBLISH_RUNBOOK.md`.

```markdown
# <role> — память роли

> Правила памяти: `docs/guides/MEMORY_CONVENTION.md` — компакт читать целиком перед прогоном; лимит
> 1500 строк И ≤60 KB; append-only; при превышении — ротация в `agents/memory/archive/<role>/<YYYY-MM>.md`.
> Канон роли: `agents/roles/<role>.md`. Ролевые дельты правил: <нет | перечислить>.

## Durable — снимок роли
<1–5 строк: что роль делает в ЭТОМ проекте, периметр записи, ключевые роли/маршруты из PROJECT.md>

## Durable — coverage taxonomy / State
<что уже покрыто и что нет; для regression-qa — baseline SHA, coverage index>

## Durable — известные слепые зоны
(пока пусто)

## Durable — lessons learned
(пока пусто)

## Durable — routing / cross-agent
(пока пусто)

## Durable — open backlog / вопросы владельцу
(пока пусто)

## Журнал прогонов

### Run YYYY-MM-DD HH:MM — первый прогон (калибровка)
<формат записи журнала — из канона роли>
```

## 5. Порядок чтения (перед каждым прогоном)

1. Прочитать компакт **целиком**. Лимиты из §2 существуют, чтобы это правило оставалось физически
   выполнимым: распухший компакт не влезает в контекст, и BLOCKING-правило «читать целиком» молча
   нарушается.
2. Без прочитанного компакта прогон не запускается (кроме первого прогона, §4).
3. Архив подключать точечно — по ссылкам из компакта или grep по конкретному вопросу.

## 6. Ротация — кто и когда

- **Сама роль**, в конце прогона: если компакт > 1500 строк **ИЛИ > 60 KB** — перенести старейшие журнальные
  записи (целые секции прогона) в архивный файл месяца записи, оставить ⤵-указатель, выполнить сверку из
  §3.2, закоммитить вместе с обновлением памяти. Журнал ротируется ПЕРВЫМ — он почти всегда покрывает
  перерасход.
- **Backstop — роль `repo-hygiene`**: hygiene-sweep (`agents/roles/repo-hygiene.md`, Operating Loop п. 8):
  `wc -l -c agents/memory/*.md` → всё, что выше **строкового ИЛИ байтового** лимита, ротировать по этой
  конвенции; результат — в отчёт и в `agents/memory/repo-hygiene.md`. Проверять обе метрики: файл бывает в
  лимите по строкам, но вдвое сверх по байтам.
- Durable-секции не ротируются никогда; если durable-слой сам распух (мало строк, но много KB) — это сигнал на
  **консолидацию**: сгруппировать lessons по категориям, схлопнуть дословные повторы и избыточные
  ⤵-указатели. Консолидация ЛОССЛЕСС: ни один отдельный факт или ссылка на задачу не теряется; при сомнении в
  уникальности — оставить. Удаление durable запрещено.

## 7. Память и worktree

Роль, работающая в git-worktree, пишет память в файлы этого worktree и часто не успевает её закоммитить;
удаление worktree без переноса теряет память. Поэтому перед удалением любого worktree обязателен детектор:

```bash
bash scripts/agent-worktree-memory-check.sh
```

Exit 1 = найдена dirty/untracked память (или незакрытый свой lease) — каждую находку diff-инспектировать и
перенести уникальное append-only содержимое в канонический `agents/memory/<role>.md` ДО удаления worktree.
Пока детектор красный, worktree не удаляется. Сам перенос — работа роли (`repo-hygiene` как backstop): скрипт
только детектирует.
